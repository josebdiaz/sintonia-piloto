Trabajar el repositorio de Sintonía con ChatGPT y Claude

Katherine y José trabajan desde ciudades distintas, con asistentes distintos. El repositorio josebdiaz/sintonia-piloto en GitHub será el lugar donde ambos asistentes leen la misma versión del proyecto. Katherine actualiza la documentación directamente y propone los cambios al prototipo para que José los revise.

Katherine · 20 minutos

Crear la cuenta, aceptar la invitación y conectar GitHub en ChatGPT. Todo desde el navegador, sin terminal.

José · 10 minutos, una vez

Invitar a Katherine con permiso de escritura y dar acceso a las apps de ChatGPT y Claude.

Katherine

Pasos para Katherine

Hazlos en este orden. Entre el paso 4 y el 5 puede haber una espera de unos 5 minutos mientras ChatGPT reconoce el repositorio.

  1. Crea tu cuenta de GitHub (si no tienes una)

    Entra a github.com/signup, usa tu correo y elige un nombre de usuario. Es gratis.

    Envíale a José tu nombre de usuario (no tu contraseña). Lo ves arriba a la derecha al hacer clic en tu foto.

  2. Acepta la invitación de José

    Te llegará un correo de GitHub. Abre el enlace y pulsa Accept invitation.

    Si no ves el correo, entra directo a github.com/josebdiaz/sintonia-piloto/invitations con tu sesión abierta.

  3. Revisa que ves el proyecto

    Abre github.com/josebdiaz/sintonia-piloto. Deberías ver las carpetas piloto, backend, datos y docs.

  4. Conecta GitHub en ChatGPT

    • En ChatGPT abre Settings (Configuración) y luego Apps.
    • Busca GitHub y pulsa Connect.
    • GitHub te pedirá autorizar a ChatGPT. Acepta.
    • Cuando pregunte qué repositorios puede ver, elige solo josebdiaz/sintonia-piloto.

    Si el repositorio de José no aparece en la lista, avísale: él tiene que dar acceso a la app de ChatGPT desde su cuenta (paso 3 de José).

  5. Prueba que funciona

    Espera unos 5 minutos y escribe en un chat nuevo:

    Usa GitHub. En el repositorio josebdiaz/sintonia-piloto, lee docs/protocolo-m2.md
y resúmeme la regla I9 y las contingencias del piloto.

    Si responde con el contenido del protocolo, ya quedó conectado.

    En algunos planes de ChatGPT la app de GitHub no aparece en el chat normal, pero sí en Deep Research o en el modo agente. Si no te funciona en el chat, prueba ahí.

  6. Actualiza la documentación directamente

    Todo lo que está en docs lo puedes cambiar tú, desde la web de GitHub:

    • Subir un archivo nuevo: entra a docs, pulsa Add file y luego Upload files.
    • Editar un archivo: ábrelo y pulsa el lápiz (Edit). Puedes pegar ahí el texto que te preparó ChatGPT.
    • Pulsa Commit changes, escribe qué cambiaste (por ejemplo docs: notas de la retro W1) y deja marcado Commit directly to the main branch.

    Dos archivos de docs se generan desde el computador de José y se sobrescriben cuando él publica: protocolo-m2.md y deck-pivote.html. Para cambiarlos, usa el camino del paso 7.

  7. Propón cambios al prototipo con un pull request

    Las carpetas piloto y backend son lo que están usando los grupos, así que ahí los cambios pasan primero por José:

    • Abre el archivo que quieres cambiar (por ejemplo piloto/plan.html) y pulsa el lápiz (Edit).
    • Haz el cambio, o pega el que te preparó ChatGPT.
    • Pulsa Commit changes y elige Create a new branch for this commit and start a pull request. Ponle un nombre corto, como katherine/texto-votacion.
    • En la página siguiente explica qué cambia y por qué, y pulsa Create pull request.

    José lo revisa, comenta si hace falta y lo integra. No lo fusiones tú.

    Si la idea todavía no es un cambio concreto (por ejemplo «el botón de veto confunde»), abre un Issue en el repositorio en lugar de un pull request.

Pasos para José (una sola vez)

En el Mac, abre la app Terminal y pega cada bloque. El inicio de sesión se hace en el navegador: no hay que copiar contraseñas ni claves en la terminal.

  1. Instala GitHub CLI e inicia sesión

    Si ya tienes Homebrew, salta la primera línea. brew -v te dice si lo tienes.

    # 1. Homebrew (solo si no lo tienes)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 2. GitHub CLI
brew install gh

# 3. Inicia sesión: elige GitHub.com → HTTPS → Login with a web browser
gh auth login
gh auth status

  2. Invita a Katherine con permiso de escritura

    Cambia USUARIO_DE_KATHERINE por el nombre de usuario que te envió.

    # Invitación con escritura: puede subir a docs y abrir ramas y pull requests
gh api -X PUT repos/josebdiaz/sintonia-piloto/collaborators/USUARIO_DE_KATHERINE -f permission=push

# Comprueba que la invitación quedó pendiente
gh api repos/josebdiaz/sintonia-piloto/invitations --jq '.[].invitee.login'

    Cuando ella acepte, la invitación desaparece de esa lista y su usuario aparece con gh api repos/josebdiaz/sintonia-piloto/collaborators --jq '.[] | .login + " " + .role_name', con el rol write.

  3. Da acceso al repositorio a las apps de ChatGPT y Claude

    El repositorio es tuyo, así que las apps solo lo ven si tú les das acceso. Esto se hace en la web:

    • Abre github.com/settings/installations.
    • App de ChatGPT: si ya aparece, pulsa Configure y en Repository access agrega sintonia-piloto. Si no aparece, la instalación se ofrece cuando Katherine conecta GitHub en ChatGPT; si el repositorio no le sale, busca en GitHub la app de ChatGPT (suele aparecer como «ChatGPT Codex Connector») e instálala solo en sintonia-piloto.
    • App de Claude: pulsa Configure, confirma que sintonia-piloto está en Repository access y que el permiso de Contents es Read and write. Si GitHub muestra «permissions update requested», acéptalo. Esto quita el error 403 que hoy impide que Claude haga commits.

  4. Cuando Katherine abra un pull request al prototipo

    publicar.sh copia piloto/, backend/, datos/ y docs/protocolo-m2.md desde tu carpeta de trabajo y reemplaza lo que haya en main. Si fusionas su pull request en GitHub y luego corres el script, su cambio se pierde.

    Para no perderlo, lleva su cambio a tu carpeta de trabajo primero (o pídele a Claude que lo haga) y publica con el script como siempre. Luego cierra el pull request con un comentario que diga en qué versión entró.

    # Ver los pull requests abiertos y el cambio de uno
gh pr list --repo josebdiaz/sintonia-piloto
gh pr diff NUMERO --repo josebdiaz/sintonia-piloto

# Después de publicar con publicar.sh, ciérralo con una nota
gh pr close NUMERO --repo josebdiaz/sintonia-piloto --comment "Integrado en piloto vX.Y.Z"

    Los cambios de Katherine en el resto de docs no tienen este problema: el script hace un merge «fast-forward» con lo que haya en GitHub antes de copiar.

Preparado el 6 de octubre de 2026. Los menús de ChatGPT y GitHub pueden cambiar de nombre; según la ayuda de OpenAI, la conexión está en Settings → Apps → GitHub y el repositorio puede tardar unos 5 minutos en aparecer.
